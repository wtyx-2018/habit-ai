## 1. 项目背景

### 1.1 产品定位

一款**面向个人的、以「习惯设计 + 环境设计」为核心的自我管理系统**。它不只是待办清单，而是通过「目标对齐 → AI 拆解任务 → 在工作日晚上与周末按时间方案派发 → 打卡完成 → 当日复盘 + 感受记录 → 记账与三张表 → 长期沉淀成可导出的 Markdown → AI 定期梳理审计」的完整闭环，帮助使用者缓解焦虑、走出对未来的迷茫，并持续增强元认知能力。

一句话概括：**把"想成为什么样的人"翻译成"今晚/这个周末这 5 分钟做什么"，并把每天发生的一切沉淀成一份可以长期回看、可供 AI 审计的个人数据资产。**

### 1.2 业务目标（个人目标）

| 目标 | 衡量方式 | 目标值（V1.0 试运行 8 周） |
| --- | --- | --- |
| 降低行动启动阻力 | 记录的任务中，被拆解为 5–30 分钟子任务的比例 | ≥ 90% |
| 建立稳定记录习惯 | 连续完成"每日复盘 + 感受"的天数 | ≥ 21 天 |
| 形成长期数据资产 | 长期总 md 文件累积的记录条数 | ≥ 300 条 |
| 建立财务全局观 | 完成记账并生成三张表的完整月份 | ≥ 2 个完整月 |
| 保持方向一致 | 与目标金字塔对齐的子任务占比 | ≥ 70% |
| 提升元认知 | 每周 AI 审计报告中被采纳并转化为行动的建议数 | ≥ 1 条/周 |

### 1.3 目标用户

**用户画像（单用户，即本人）：**

- 有强烈的自我提升意愿，正在做"习惯设计 / 环境设计"的实践。
- 处于焦虑、对未来迷茫的状态，需要通过**记录与外部视角**获得掌控感。
- **主要可用时间在工作日晚上与周末**，早晨不是主要使用时段。
- 日常事务分布在多个领域：**运动、开发、学习、工作事项、每日记账、当日复盘与感受**。
- 认同"反向思维"与"Stop Doing List"理念（查理·芒格、段永平的"不为清单"），需要长期维护一份原则性的"不做什么"清单。
- 希望自己产生的一切记录能够**沉淀成 Markdown 文件**，交给 AI 做定期梳理、分析与审计。
- 具备一定的动手能力，愿意自己提供大模型 API Key 来完成 AI 功能。

### 1.4 价值主张

| 维度 | 价值 |
| --- | --- |
| 对用户 | 把大而空的目标切成 5–30 分钟可执行的小动作，降低启动成本；用记录 + 复盘替代焦虑反刍；用 AI 审计提供外部视角，增强元认知 |
| 对环境 | 通过"不为清单"、时间方案与每日任务派发，主动设计注意力和时间环境，减少内耗与选择成本 |
| 对方向 | 用目标金字塔把每天的小事对齐到长期方向，治疗"对未来迷茫" |
| 对长期 | 所有记录沉淀为一份可持续累积的总 md 文件 + 个人财务三张表，形成可被 AI 长期分析的"个人数据库" |

### 1.5 应用场景

- **主场景：** Android 手机端日常使用，使用高峰在**工作日晚上（下班之后）与周末**：傍晚看今晚任务、晚上打卡与复盘记账；周末白天安排需要整块时间的深度任务。
- **数据场景：** 数据以本地为主，支持导出 md 到手机指定目录或云盘做备份与外部 AI 分析。
- **不使用场景：** 多用户协作、社交分享、公开排行榜（V1.0 明确不做）。

## 2. 需求概述

### 2.1 用户痛点

| 编号 | 痛点 | 具体表现 |
| --- | --- | --- |
| P-1 | 焦虑与迷茫 | 想做的事太多，不知道从哪开始，越想越焦虑，对未来没有方向感 |
| P-2 | 任务无法启动 | 计划写成"学习某某""做某某项目"，颗粒度太大，看到就不想动 |
| P-3 | 时间没有被"安排" | 主要时间在工作日晚上和周末，但没有被提前布置任务，时间在无意识中流失 |
| P-4 | 记录分散无沉淀 | 想法、复盘、账目散落在备忘录/微信/纸质本，无法累积成资产 |
| P-5 | 缺乏财务全局 | 只记流水，不知道自己的资产、负债、现金流全貌 |
| P-6 | 缺少外部视角 | 自己复盘容易陷入自我叙事，没有第三方（AI）来做审计和追问 |
| P-7 | 激励不个性化 | 通用的鸡汤激励对自己无效，需要基于自身人格和偏好的激励 |
| P-8 | 缺乏方向结构 | 每天很忙，但说不清这些事是否通向自己真正想去的方向 |
| P-9 | 情绪来袭无抓手 | 焦虑/低落发生的当下没有即时干预手段，只能被动承受或内耗 |

### 2.2 业务价值

- **降低启动成本：** 把任务拆到 5–30 分钟，让"开始"这件事几乎不需要意志力。
- **建立环境：** 按工作日/周末时间方案派发任务 + 长期"不为清单"，主动设计注意力环境。
- **对齐方向：** 目标金字塔让每天的小事都能追溯到长期方向。
- **沉淀资产：** 所有记录汇入一份长期总 md 文件，可长期回看、可交给 AI 分析。
- **获得外部视角：** AI 定期梳理 + 审计 + 激励，提供自己给不了自己的视角。
- **情绪有出口：** 焦虑急救在情绪发生当下提供即时、结构化的疏解。
- **财务清晰：** 从"记流水"升级到"个人三张表"，看清自己的财务结构。

### 2.3 预期收益（个人化指标）

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 任务拆解率 | 被拆解为 5–30 分钟子任务的主任务占比 | ≥ 90% |
| 子任务完成率 | 当日派发子任务的完成比例 | ≥ 70% |
| 连续记录天数 | 连续完成"复盘 + 感受"的天数 | ≥ 21 天 |
| 记账完整度 | 当月有记账的天数占比 | ≥ 85% |
| 总 md 文件条数 | 长期总文件中累积的记录条数 | 8 周 ≥ 300 条 |
| 目标对齐率 | 关联到上级目标的子任务占比 | ≥ 70% |
| AI 建议采纳率 | 每周审计建议中转化为行动的比例 | ≥ 1 条/周 |

### 2.4 版本范围

**V1.0（本次）包含 6 大模块：**

1. 任务核心闭环：记录任务 → AI 拆解成 5–30 分钟子任务 → 按工作日/周末时间方案派发 → 完成打卡
2. 每日复盘 + 感受记录 + 每日记账（含个人三张表分析）
3. 不为清单（芒格 / 段永平式的长期原则清单）
4. 长期总 md 文件 + 导出备份
5. AI 定期分析（梳理 / 审计 / 激励）
6. 自我设计增强：目标金字塔（方向对齐）、习惯与环境设计（五要素）、焦虑急救（情绪干预）

**V1.0 不包含：** 云端同步与账号体系、iOS 端、多用户、社交分享、图表高级可视化、App 指纹锁与自动定时备份（V1.1 起逐步补充）。

## 3. 用户需求与功能需求

### 3.1 用户需求

**目标用户：** 单一使用者本人（个人自用型工具）。

**核心使用场景：**

| 场景 | 触发条件 | 用户行为 | 期望结果 |
| --- | --- | --- | --- |
| 工作日傍晚看任务 | 工作日下班前后（如 18:30） | 打开 App 查看"今晚任务" | 明确晚上做什么，心里有底 |
| 周末看任务 | 周末上午（如 09:30） | 查看当天任务（含深度任务） | 把周末整块时间用起来 |
| 随手记任务 | 任何时候有想法 | 输入一件事（如"整理开发文档"），可关联目标 | AI 自动拆解成 5–30 分钟子任务 |
| 打卡 | 完成一个子任务后 | 点击完成 | 获得即时反馈，累积成就感 |
| 记账 | 发生收支时或晚上统一记 | 录入一笔收支 | 自动归入当月三张表 |
| 晚间复盘 | 每天固定时间（如 22:00） | 写当日复盘 + 感受 | 当日内容沉淀进总 md 文件 |
| 焦虑急救 | 感到焦虑/低落/迷茫时 | 进入急救入口，跟做 2–3 分钟引导 | 情绪强度下降，有一个最小行动 |
| 维护不为清单 | 不定期 | 新增/修订"我长期不做的事" | 形成稳定的行为边界 |
| 维护目标 | 每周/每季度 | 拆解与对齐目标 | 确保每天的事通向长期方向 |
| 导出与备份 | 每周 / 每月 | 一键导出 md | 生成/更新长期总 md 文件 |
| 查看 AI 分析 | 每周 / 每月 | 查看 AI 生成的梳理、审计、激励报告 | 获得外部视角与个性化激励 |

**核心需求（用户视角）：**

1. "我把一件事丢进去，它帮我拆成我马上就能开始做的小步骤。"
2. "它知道我主要在工作日晚上和周末有空，会把任务安排在这些时间段，我不用自己纠结做什么。"
3. "我每天写几句复盘和感受，它自动沉淀下来，不会丢。"
4. "我记的账能自动变成资产、收支、现金流三张表，让我看清自己。"
5. "我有一份长期的原则清单，提醒我什么绝对不做。"
6. "我焦虑的时候，它能立刻带我做几分钟疏解，而不是让我干扛着。"
7. "它能告诉我，我每天忙的这些事，到底有没有在靠近我想去的方向。"
8. "所有东西能导出成 md，交给 AI 定期帮我梳理、审计、鼓励我。"

## 4. 业务流程

### 4.1 每日主流程

```
工作日傍晚 / 周末上午（按时间方案推送，不设晨间提醒）
  1. 工作日：下班前后（默认 18:30）推送"今晚任务已就绪"；
     周末：上午（默认 09:30）推送"今日任务已就绪"
  2. 用户打开查看今日子任务清单（由 F-03 按当天可用时段派发，显示所属目标）
  3. 用户确认/微调（拖拽调整、顺延、删除）

可用时段内（工作日晚上 / 周末全天分段）
  4. 随时录入新任务（可关联目标）→ AI 拆解 → 加入今日或待办池
  5. 每完成一个子任务 → 打卡（记录耗时）
  6. 发生收支 → 随手记账
  7. 习惯最小行动按触发锚点出现 → 完成或执行降级版本
  8. 感到焦虑/低落 → 进入焦虑急救，跟做 2–3 分钟引导

晚间（固定时间，默认 22:00）
  9. App 推送"今日复盘提醒"
  10. 用户填写复盘（完成/未完成/原因/明日重点）
  11. 用户记录感受 + 情绪标签
  12. 用户补齐当日账目
  13. 系统将当日全部内容写入本地库，并标记"待汇总进总 md 文件"

周期触发
  14. 每周/每月：一键导出 → 更新长期总 md 文件
  15. 每周/每月：AI 生成梳理 / 审计（含目标对齐）/ 激励报告
```

### 4.2 任务拆解与派发流程

```
1. 用户输入任务（例：整理开发文档），可关联一个上级目标
2. App 调用 AI，传入：任务描述 + 所属领域 + 用户画像/偏好（可选）
3. AI 返回子任务列表，每条含：
   - 子任务描述
   - 预估时长（5–30 分钟）
   - 任务类型（轻量 / 深度）
   - 建议执行时段（可选）
   - 完成判定标准（可选）
4. App 展示拆解结果，用户可：编辑 / 删除 / 新增 / 合并 / 重新拆解
5. 用户确认后，子任务进入"待办池"
6. 派发逻辑：读取当天（按星期几）的可用时段，依据
   "任务类型 × 时段标签 × 时长"匹配排入当天
   - 工作日晚间：优先 ≤15 分钟轻量任务（运动、复盘、小段学习、习惯）
   - 周末大段时间：优先深度任务（开发、系统学习、项目推进）
   - 超出当日可容纳量的子任务进入"待办池"，顺延到下一个匹配时段
```

**异常分支：**

| 情况 | 处理 |
| --- | --- |
| AI 返回的子任务时长 > 30 分钟 | 自动二次拆解或提示用户手动拆分 |
| AI 返回子任务 < 5 分钟且过于琐碎 | 提示合并 |
| API 调用失败/超时（> 15 秒） | 降级为"手动拆解"模式，保留原任务，提示可重试 |
| 未配置 API Key | 提示前往设置配置，任务暂存为"未拆解" |
| 某天未配置任何可用时段 | 不派发任务，仅保留待办池，提示"今天没有安排时间" |

### 4.3 记账与三张表流程

```
1. 用户录入一笔收支（金额、方向、分类、账户、日期、备注）
2. 系统写入流水表
3. 自动归集：
   - 收支表：按期间（日/周/月）汇总收入、支出、结余
   - 资产负债表：按账户（现金/银行卡/投资/负债）汇总资产、负债、净资产
   - 现金流量表：按经营/投资/筹资三类归集现金流
4. 用户可查看三张表，并导出到总 md 文件
5. AI 可基于三张表做财务分析与建议
```

**说明：** 个人三张表在个人场景下做简化处理——「资产负债表」看"我拥有什么、欠什么"，「收支表」看"这段时间赚了花多少、结余多少"，「现金流量表」看"钱实际怎么流动的"。账户科目体系【待确认】。

### 4.4 导出与长期总文件流程

```
1. 用户点击"导出"
2. 系统读取自上次导出以来新增/变更的记录
3. 按固定结构更新长期总 md 文件（life_log.md）：
   - 更新目标金字塔区块（目标及对齐进度）
   - 追加当日记录区块（任务 / 复盘 / 感受 / 账目摘要 / 习惯打卡 / 焦虑急救）
   - 更新汇总区块（统计、三张表快照、不为清单）
4. 文件写入用户指定目录（本地 / 云盘同步目录）
5. 提示"导出成功，共更新 X 条记录"
```

**异常分支：** 目标目录无写权限 → 提示用户重新选择目录；写入失败 → 保留待导出队列，下次重试。

### 4.5 AI 定期分析流程

```
1. 触发：用户手动触发 或 到达设定周期（每周/每月）
2. 系统打包本期数据（任务完成、目标对齐、复盘、感受、账目、不为清单、习惯、焦虑记录）
3. 调用 AI，按分析类型生成：
   - 梳理：这段时间做了什么、有什么模式
   - 审计：哪些承诺没兑现、哪些模式在重复、哪些建议未执行、
           哪些子任务偏离了目标金字塔、哪些目标长期无进展
   - 激励：基于人格画像给出个性化激励与下一步建议
4. 结果写入 App，并可合并进总 md 文件
5. 用户可对报告标记"有用/没用"，用于后续优化
```

### 4.6 焦虑急救流程

```
触发：感受记录选择"焦虑/低落/迷茫"，或首页快捷入口手动进入
1. 强度评估：现在情绪强度 1–5
2. 着陆：30–60 秒呼吸引导（本地文案/动画，不依赖 AI）
3. 写下：触发事件、脑中的自动想法、身体感受
4. AI 追问（苏格拉底式）：
   - 这是事实还是我的想法？
   - 最坏情况我能否应对？有没有相反证据？
   - 一年后这件事还重要吗？
5. 再评估：干预后情绪强度；输出一句基于人格画像的安抚 + 一个最小行动
6. 全过程自动写入本地库与总 md「焦虑急救记录」
（无网络/API 不可用 → 纯本地版：呼吸引导 + 书写模板 + 预设追问卡片）
```

### 4.7 异常流程汇总

| 异常 | 处理 |
| --- | --- |
| 网络异常（AI 调用） | 降级为离线模式，功能可用，AI 功能提示稍后重试；焦虑急救降级为纯本地版 |
| AI 返回格式错误 | 重试 1 次；仍失败则展示原始文本并提示手动整理 |
| 通知权限未开启 | 首次使用引导开启；未开启时 App 内顶部常驻提示 |
| 存储权限未授予 | 导出时引导授权；未授权时导出到 App 私有目录并提示 |
| App 被杀死导致数据未保存 | 关键输入实时本地落库（草稿自动保存） |

### 4.8 状态流转

**任务状态：** 未拆解 → 已拆解（待派发）→ 已派发（今日）→ 进行中 → 已完成 / 已跳过 / 已顺延

**目标状态：** 草稿 → 进行中 → 已达成 / 已调整 / 已归档（保留变更历史）

**导出状态：** 待导出 → 导出中 → 已导出 / 导出失败（可重试）

**AI 分析状态：** 空闲 → 生成中 → 就绪 / 失败（可重试）

### 6.2 任务管理模块（F-01 ~ F-04、F-03a）

**界面设计**

- 首页顶部为"今日任务"卡片列表，每张卡片显示：子任务描述、预估时长、所属领域、所属目标标签、完成按钮。
- 底部悬浮按钮"＋"快速录入任务。
- 录入弹窗：任务描述（必填）、领域（单选：运动/开发/学习/工作/其他）、优先级、关联目标（可选，选自目标金字塔）。

**时间方案设置（F-03a）**

- 按星期几配置可用时段，默认区分工作日与周末两套，可逐天微调。
- 一天支持多个时段（如周末 09:30–12:00、14:00–18:00、19:30–22:30）。
- 每个时段标记适合的任务类型：轻量 / 深度 / 不限。
- 派发提醒时间独立配置（工作日傍晚、周末上午）。

**交互逻辑**

- 输入任务 → 点击"AI 拆解" → 显示加载态（超时 15 秒）→ 展示子任务列表。
- 每条子任务可：编辑文案、调整时长（5/10/15/20/30 分钟快捷选项）、删除、标记"合并"、切换轻量/深度。
- 确认后，系统依据当天时间方案自动匹配排入今日；工作日晚间优先轻量短任务，深度任务优先排入周末时段；超出容量进入"待办池"。
- 完成打卡：点击圆形按钮 → 状态变更为"已完成" → 显示轻量反馈（如"✓ 又完成一件"）。
- 跳过/顺延：长按或右滑菜单；顺延时自动推荐下一个匹配时段。

**技术方案**

- 本地数据库（SQLite / Room）存储任务与子任务。
- AI 拆解通过统一的大模型调用层，Prompt 中约束"每条子任务耗时必须在 5–30 分钟之间"并输出轻量/深度类型。
- 提醒通过系统本地通知（AlarmManager / WorkManager），按时间方案调度。

### 6.3 目标金字塔模块（F-23）

**定位：** 治疗"对未来迷茫"的顶层模块。让每天 5 分钟的动作都能向上追溯到长期方向；AI 审计据此追问"今天做的事是否通向你想去的方向"。

**层级结构：** 愿景（想成为什么样的人 / 过什么样的生活）→ 年度目标（建议 3–5 个）→ 季度目标 → 本周计划 → 今日子任务。

**界面设计**

- "目标"页采用金字塔 / 时间线视图，自上而下展示四层。
- 目标卡片：标题、层级、上级目标、截止时间、状态、关联子任务数与完成进度。
- 首页今日子任务显示所属目标标签（如「年度目标 · 健康」）。

**交互逻辑**

- 新建任务 / AI 拆解子任务时，可关联一个叶子目标（周计划或季度目标），允许事后补关联。
- 周计划可由季度目标拆解生成（手动或 AI 辅助）。
- AI 周报/审计输出"目标对齐度"：与目标无关的时间消耗、长期无进展的目标、目标之间的冲突。
- 目标可调整 / 归档，变更记录写入总 md，保留演进过程。

### 6.4 习惯与环境设计模块（F-14）

**定位：** 把"习惯设计 + 环境设计"方法论产品化，核心是**降低启动阻力、让好习惯几乎自动发生**。

**每个习惯包含五要素：**

1. **习惯名称**：如"俯卧撑"。
2. **触发锚点**：绑定到已有行为或固定时间，如"下班换完衣服后"。
3. **最小行动**：低到不可能失败的版本，如"只做 1 个俯卧撑"。
4. **环境预置**：提前布置环境，如"睡前把俯卧撑垫铺在床边显眼处"。
5. **降级版本**：状态差时的保底动作，确保链条不断（如改做 1 个深蹲）。

**界面设计：** 习惯卡片墙，每张卡片显示连续天数（streak）、今日状态、触发锚点。

**交互逻辑**

- 最小行动可作为 5 分钟子任务派发到今日清单，与任务体系打通。
- "不想做"时不提供直接跳过，而是引导执行降级版本并记录原因。
- 断链不惩罚：显示"重建链条"，AI 在复盘中分析触发因素而非追责。
- 环境预置支持提醒（如晚上提醒"把垫子铺好"）。

### 6.5 每日复盘与感受模块（F-05、F-06）

**界面设计**

- 晚间提醒进入复盘页，采用结构化模板：
  - 今日完成（自动带出已打卡子任务，可补充）
  - 未完成及原因（自由文本）
  - 明日重点（自由文本）
  - 今日感受（自由文本）
  - 情绪标签（多选）+ 情绪强度（1–5）

**交互逻辑**

- 支持草稿自动保存，防止误退出丢失。
- 当情绪标签选择"焦虑/低落/迷茫"时，弹出"需要现在做 2–3 分钟疏解吗？"入口（可跳过）。
- 提交后生成"今日记录区块"，等待汇总进总 md 文件。

### 6.6 焦虑急救模块（F-24）


**异常处理：** 无网络或 API 不可用时，提供纯本地版本（呼吸引导 + 书写模板 + 预设追问卡片）。

### 6.7 记账与个人三张表模块（F-07、F-08）

**界面设计**

- 记账页：金额输入键盘、收/支切换、分类选择、账户选择、备注。
- 财务页：三个标签页（资产负债 / 收支 / 现金流），展示当期汇总与明细。

**三张表定义**

| 表 | 内容 | 更新方式 |
| --- | --- | --- |
| 资产负债表 | 各账户余额（现金、银行卡、投资、负债），净资产 = 资产 − 负债 | 每次记账后更新账户余额 |
| 收支表（利润表） | 期间收入、支出、结余 | 按日/周/月汇总流水 |
| 现金流量表 | 经营 / 投资 / 筹资三类现金流净额 | 按流水分类归集 |

**交互逻辑**

- 记一笔账 → 自动更新对应账户余额与三张表。
- 支持编辑/删除历史流水，删除后三张表自动重算。
- 一键把当期三张表快照写入总 md 文件。

**待确认：** 账户科目体系、分类体系是否需要自定义。【待确认】

### 6.8 不为清单模块（F-09）

**定位说明（重要）**

这不是"今天不做什么"的临时清单，而是**长期、原则性的"Stop Doing List"**——借鉴查理·芒格的反向思维与段永平的"不为清单"，回答"我这一生长期不做什么"。它的作用是**通过明确边界来设计环境、减少内耗、避免在错误方向上消耗自己**。

**界面设计**

- 清单以"原则卡片"形式展示，每张卡片包含：
  - 不为事项（例："不熬夜刷短视频"）
  - 背后理由（为什么不做）
  - 归类（如：注意力 / 健康 / 财务 / 关系 / 事业）
  - 加入日期、修订记录

**交互逻辑**

- 新增 / 编辑 / 归档（不删除，保留历史，体现"原则的演进"）。
- 每日复盘页底部展示 1–3 条随机/轮换的"不为清单"提醒，强化记忆。
- 总 md 文件中保留完整不为清单及其修订历史。

### 6.10 AI 分析与激励体系（F-12、F-15、F-16）

| 定期梳理 | 本期任务/复盘/感受 | 这段时间做了什么、有什么模式 | 每周/每月 |
| 定期审计 | 本期 + 历史数据 + 目标金字塔 | 未兑现承诺、重复模式、未执行建议、**子任务与目标偏离、长期无进展目标** | 每周/每月 |
| 焦虑急救 | 当下情绪强度 + 触发事件与想法 | 呼吸引导、苏格拉底式追问、认知重构、一句安抚 + 一个最小行动 | 情绪标记为焦虑/低落/迷茫时 |
| 激励设计 | 人格画像 + 近期状态 | 个性化激励语、里程碑、下一步建议 | 每周/每月 或 低落时 |
| 人格画像 | 长期全部记录 | persona.md（持续更新） | 每月 或 手动触发 |

**人格画像文件（persona.md）草案**

```markdown
# 我的人格画像（AI 持续更新）
- 核心价值观：…
- 行为模式：…
- 情绪触发点：…
- 对我真正有效的激励方式：…
- 我容易陷入的陷阱：…
- 更新日期：YYYY-MM-DD
```

**激励设计原则**

- **个性化：** 基于人格画像生成，不使用通用鸡汤。
- **基于事实：** 激励内容引用用户自己的真实记录（如"你已经连续 14 天记录"）。
- **可执行：** 每条激励附带一个具体的小行动。
- **反向视角：** 结合"不为清单"，用"你没做什么"来强化边界感。

**技术方案**

- 统一大模型调用层，支持配置 Base URL + API Key（兼容 OpenAI 协议）【待确认】。
- 长文本分析采用分块 + 摘要策略，控制 token 成本。
- 所有 AI 输出本地缓存，避免重复调用。

## 7. 数据埋点与本地统计

由于是个人自用产品，不做服务端埋点，改为**本地使用统计**，用于自我回顾与 AI 分析：

| 统计项 | 说明 | 用途 |
| --- | --- | --- |
| 每日任务数 / 完成数 | 按领域拆分 | 完成率趋势 |
| 子任务平均时长 | 实际 vs 预估 | 拆解质量评估 |
| 连续记录天数 | 复盘 + 感受 | 习惯养成 |
| 情绪标签分布 | 按周/月 | 情绪趋势 |
| 记账完整度 | 当月记账天数占比 | 财务习惯 |
| AI 报告使用情况 | 生成次数、有用/没用反馈 | 优化 AI 输出 |
| 目标对齐率 | 关联到上级目标的子任务占比 | 方向一致性 |
| 习惯连续天数 | 各习惯打卡链条（降级版完成视为不断链） | 习惯养成 |
| 焦虑干预效果 | 使用次数、干预前后情绪强度变化 | 情绪干预有效性 |

**关键指标：**

- 子任务完成率 = 当日完成子任务数 / 当日派发子任务数
- 拆解合理率 = 预估时长与实际耗时偏差 < 50% 的子任务占比
- 连续记录天数 = 连续满足"复盘 + 感受"的日历天数
- 目标对齐率 = 关联目标的子任务数 / 子任务总数

## 9. 风险与异常

### 9.1 潜在风险

| 风险类型 | 风险描述 | 等级 | 应对措施 |
| --- | --- | --- | --- |
| 产品风险 | 功能过多导致初期使用负担重，反而加重焦虑 | 高 | V1.0 严格按 P0 落地，界面保持极简，复盘模板预设好、只需填空；新功能默认收起、按需开启 |
| 产品风险 | 目标金字塔/复盘填表过重，坚持不下去 | 中 | 愿景/年度目标低频维护；日常只需打卡 + 三句话复盘，其余可留空 |
| 技术风险 | AI 拆解质量不稳定（时长不合理、过于笼统） | 中 | Prompt 强约束时长范围 + 用户可编辑 + 支持重新拆解 |
| 技术风险 | 大模型 API 费用不可控 | 中 | 本地缓存结果、限制分析频率、长文本分块摘要 |
| 数据风险 | 数据仅本地，换机/卸载丢失 | 高 | 提供手动导出备份并提醒定期备份；V1.1 增加自动备份/云同步 |
| 数据风险 | 导出文件被外部修改产生冲突 | 低 | 文件指纹检测 + 覆盖/另存提示 |
| 隐私风险 | 记录内容（含感受、焦虑、账目）发送给大模型 | 中 | 数据本地存储、默认不发送；AI 功能需用户知情并可开关【待确认】 |
| 使用风险 | 焦虑急救给出不恰当建议 | 中 | 明确"非医疗服务"，内容以引导书写与认知重构为主；严重情绪问题提示寻求专业帮助 |
| 使用风险 | 坚持不下去，记录中断 | 中 | 降低每日记录门槛 + AI 激励 + 连续记录天数可视化 |

### 9.2 边界条件

**业务边界**

- 单人使用，无多用户。
- 子任务时长约束 5–30 分钟。
- 每日派发的子任务总量受当天可用时段容量限制，超出进入待办池。
- 未配置可用时段的日期不派发任务。
- 不为清单只归档不删除，保留修订历史。
- 焦虑急救为自助式情绪记录与引导，不构成心理/医疗诊断。

**技术边界**

- 单次 AI 请求文本长度受模型上下文限制，超长内容分块处理。
- 本地数据库容量建议 ≤ 10 万条记录，超出提示归档。
- 导出文件单次更新建议 ≤ 5000 条记录。

**数据边界**

- 金额精度：小数点后 2 位。
- 情绪强度：1–5 整数。
- 单条复盘/感受文本：建议 ≤ 5000 字。
